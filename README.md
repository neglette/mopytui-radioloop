# mopytui · Radio Loop

Терминальный клиент Mopidy с независимым интернет-радио, коллекциями станций,
автоматической ротацией, плавными переходами и управлением через обычный `mpc`.
Форк [prietus/mopytui](https://github.com/prietus/mopytui). Версия: **0.1.1-radio.15**.

Музыка воспроизводится сервером Mopidy, радио — локальным GStreamer-проигрывателем.
Запуск радио ставит музыку на паузу. Запуск музыки останавливает радио.
После остановки радио музыка сама не возобновляется.

## Возможности

- Вкладки **Queue, Albums, Library, Playlists, Playing, Radio, Info**.
- Очередь, альбомы с обложками, дерево библиотеки и плейлисты Mopidy.
- Обычное воспроизведение, громкость, перемотка и режимы Mopidy.
- Обложки через доступный терминалу протокол; режим `halfblocks` без графического протокола.
- Тексты песен и дополнительные сведения об альбомах при доступности внешних сервисов.
- Поиск Radio Browser по имени и тегам, проверка реального декодирования звука.
- Одновременно видимые поле поиска, результаты и список воспроизведения.
- Смена станции через случайные 23–37 минут по умолчанию, ручные Next/Previous.
- Fade-out / переключение / fade-in, обработка обрывов и смена сетевого маршрута.
- Именованные коллекции станций, редактируемые интервалы и фейды.
- SOCKS5/HTTP-прокси, прямое подключение, буферизация, звуковые сигналы запуска/остановки.
- MPD-шлюз для существующих медиаклавиш и дополнительный виджет Awesome WM.

## Зависимости и сборка

Основная целевая платформа форка — **Linux**. Готовый архив рассчитан на Linux x86-64;
совместимость его системных библиотек с любым дистрибутивом не гарантируется.
При несовместимости соберите проект локально.

Для музыки нужен доступный Mopidy с HTTP JSON-RPC и расширением Mopidy-MPD.
Для радио нужны Python 3, PyGObject (`gi`), GStreamer 1.0, декодеры аудио и `curl`.
Установщик шлюза использует Python 3.11+ (`tomllib`) и пользовательский systemd.

Пример зависимостей радио для Debian/Ubuntu (доступность пакетов зависит от выпуска):

```sh
sudo apt install curl python3 python3-gi gir1.2-gstreamer-1.0 \
  gstreamer1.0-tools gstreamer1.0-plugins-base gstreamer1.0-plugins-good \
  gstreamer1.0-plugins-bad gstreamer1.0-plugins-ugly gstreamer1.0-libav mpc
```

Проверка Python/GStreamer:

```sh
python3 -c 'import gi; gi.require_version("Gst", "1.0"); from gi.repository import Gst; Gst.init(None); print(Gst.version_string())'
```

Для сборки нужен современный Rust stable с поддержкой edition 2024. Из корня репозитория:

```sh
cargo build --release --locked
./target/release/mopytui --version
./target/release/mopytui
```

Собираются три исполняемых файла: `mopytui`, `radio-search`, `mopytui-mpd-proxy`.
Python-код аудиобэкенда встроен в бинарник, но интерпретатор и GStreamer устанавливаются отдельно.
Необязательная сборка `--features chafa` требует системной libchafa.

## Установка и обновление

Из готового архива:

```sh
tar --no-same-owner -xzf mopytui-radio-loop-v15-linux-x86_64.tar.gz
cd mopytui-radio-loop-v15
sh install-system.sh
mopytui
```

`install-system.sh` устанавливает **только TUI** в `/usr/local/bin/mopytui`,
сам вызывает sudo и сохраняет предыдущий бинарник в напечатанном каталоге резервной копии.
Конфиг пользователя, коллекции, Mopidy и установленный MPD-шлюз не перезаписываются.
Само приложение запускайте обычным пользователем, без sudo.

После сборки из исходников для того же установщика:

```sh
cp target/release/mopytui ./mopytui
sh install-system.sh
```

Чтобы отдельно установить CLI:

```sh
sudo install -m 755 target/release/radio-search /usr/local/bin/radio-search
```

Для обновления шлюза используется его отдельный установщик, описанный ниже.
Если запускается прежняя версия, проверьте `command -v mopytui` и `mopytui --version`:
локальный скрипт или файл в `~/.local/bin` может предшествовать `/usr/local/bin` в PATH.

## Первый запуск

1. Запустите Mopidy и проверьте обычное воспроизведение.
2. Запустите `mopytui`; при отсутствии конфига создаётся шаблон.
3. При необходимости задайте прокси в секции `[radio]` конфигурации.
4. Откройте Radio через Ctrl+←/→ или щелчок по вкладке.
5. Нажмите `/`, введите, например, `ambient`, затем Enter.
6. Пробел добавляет проверенную станцию; Enter добавляет и начинает воспроизведение.
7. F2 открывает параметры, F3 — сохранённые коллекции.

```sh
mopytui --host 192.168.1.10 --port 6680
mopytui 192.168.1.10:6680
mopytui --theme solar
mopytui --image-protocol halfblocks
mopytui --help
```

Даже при удалённом Mopidy радио звучит на компьютере, где запущен TUI.

## Конфигурация

На Linux: `~/.config/mopytui/config.toml` (с учётом `XDG_CONFIG_HOME`).
Параметры командной строки перекрывают соответствующие значения на текущий запуск.
Все параметры радио должны находиться **под `[radio]`**, а общие — перед этой секцией.

```toml
host = "127.0.0.1"
http_port = 6680
mpd_port = 6600 # после установки шлюза установщик меняет на 6602
theme = "midnight"

# Необязательный источник PCM для настоящего FFT:
# audio_pipe = "/tmp/mopidy.fifo"
# Необязательные ключи внешних сервисов метаданных:
# lastfm_api_key = ""
# fanart_api_key = ""
# discogs_token = ""

[radio]
proxy = "socks5h://127.0.0.1:1080" # удалите строку, если прокси не нужен
preferred_network = "proxy"      # "proxy" или "direct"
buffer_seconds = 3.0
sound_signals = true
rotation_min = 23                 # минуты
rotation_max = 37
fade_out = 1.5                    # секунды
fade_in = 2.5
retry_wait_before_restart = 3.0
retry_wait_after_restart = 5.0
station_probe_timeout = 5.0
python = "python3"
# Резервный список, только если DNS не дал зеркал:
servers = ["https://de1.api.radio-browser.info"]
```

`preferred_network = "proxy"` сам по себе не создаёт прокси. Нужен работающий
локальный/удалённый прокси и его адрес. Без адреса используется прямой доступ.
`MOPYTUI_RADIO_PROXY` перекрывает `radio.proxy`.

Допустимые интервалы: 1–10080 минут, минимум не больше максимума.
Фейды и таймауты: больше нуля, не более 300 секунд. Буфер: 0–30 секунд.
В F2 сеть, буфер и сигналы сохраняются в конфиг; интервалы и фейды действуют
в текущем сеансе. Для повторного использования сохраните их в коллекцию либо
вручную задайте в конфиге. Применение интервала запускает новый таймер.

Параметр `mpris` сохранён для совместимости конфигурации, но самостоятельная
MPRIS-интеграция в этой версии не реализована. Для медиаклавиш используйте шлюз mpc.
Не публикуйте личный конфиг с паролями прокси и ключами API.

## Радио и коллекции

Перед добавлением новой станции приложение проверяет получение декодируемого аудио
через GStreamer примерно за 5 секунд. Зелёное **OK** означает успешную проверку,
красное **DEAD** — ошибку; это состояние проверки, а не гарантия непрерывной работы станции.
Список можно менять во время воспроизведения.

При каждом переходе выбирается новый случайный интервал в заданном диапазоне.
Ручное переключение также перезапускает таймер. Станции обходятся по порядку списка;
случаен именно интервал. Переход использует один pipeline: затухание, смена URL,
нарастание громкости. Одновременный crossfade двух потоков пока не реализован.

При сбое приложение ждёт 3 секунды, один раз повторяет тот же URL и ожидает запуск
до 5 секунд с поправкой на буферизацию. Если доступен альтернативный маршрут,
пробует его; при неудаче переходит к следующей станции.
Короткий сигнал запуска звучит перед подключением и заполнением буфера,
сигнал остановки — при выключении режима. Автоматические повторные подключения
не сопровождаются сигналами. При нулевой громкости сигналы не звучат.

F3 открывает **Radio Collections**:

| Клавиша | Действие |
|---|---|
| `s` | Сохранить текущий набор под новым именем |
| `Enter` | Загрузить выбранную коллекцию |
| `u` | Обновить выбранную коллекцию текущим набором с подтверждением |
| `r` | Переименовать |
| `d` / `Delete` | Удалить с подтверждением |
| `Esc` / `F3` | Закрыть |

Коллекции сохраняются в `~/.config/mopytui/radio-collections.json`:
станции, порядок, интервалы и фейды. Сеть и пароли в коллекции не записываются.
Это отдельные наборы радио, не плейлисты Mopidy. Для переноса сохраните JSON и конфиг.

## Клавиатура и мышь

Буквенные команды поддерживают соответствующие физические клавиши русской раскладки.
В полях ввода сохраняется вводимый текст, включая кириллицу; `q` там не закрывает приложение.

| Общие клавиши | Действие |
|---|---|
| `Ctrl+←` / `Ctrl+→` | Предыдущая / следующая вкладка |
| `Tab` / `Shift+Tab` | Смена панели там, где предусмотрено |
| `1`…`7` | Прямой переход к вкладкам вне текстового ввода |
| `q` / `Q` | Выход вне текстового ввода |
| `?` | Справка |
| `Ctrl+r` | Обновить состояние Mopidy |
| `+` / `=` / `-` | Громкость активного проигрывателя, шаг 5 |

### Radio

| Клавиша | Действие |
|---|---|
| `/` / `a` | Фокус поля поиска |
| `Enter` в поиске | Запрос и переход к результатам |
| `Space` в результатах | Проверить и добавить станцию |
| `Enter` в результатах | Проверить, добавить и воспроизвести |
| `Enter` в воспроизведении | Переключиться на выбранную станцию с фейдом |
| `Space` в воспроизведении | Не выполняет действие |
| `Tab` / `Shift+Tab` | Поиск → результаты → воспроизведение / обратно |
| `↑/↓`, `k/j` | Перемещение по списку |
| `p` | Пауза / продолжение; запуск, если радио остановлено |
| `s` | Остановка радио |
| `n` / `>` и `<` | Следующая / предыдущая станция |
| `r` | Перезапуск текущей станции |
| `d` / `Delete` | Удалить станцию из списка воспроизведения |
| `J` / `K` | Передвинуть станцию вниз / вверх |
| `Esc` | Перевести фокус на воспроизведение |
| `F2` | Настройки: ↑/↓ выбирают поле, ←/→ меняют, Enter применяет, Esc отменяет |
| `F3` | Коллекции |

### Музыка

| Экран | Клавиши и действия |
|---|---|
| Воспроизведение | Space — пауза; `s` — стоп; `>`/`<` — следующий/предыдущий; `[`/`]` — перемотка ±10 с; `m` — mute |
| Playing | ←/→ — перемотка ±5 с; `L` — тексты; `c` — fit/crop обложки |
| Режимы Mopidy | `R` random, `T` repeat, `S` single, `C` consume |
| Queue | Enter — играть; `d`/Delete — удалить; `J`/`K` — переместить; `X` — очистить; `Z` — перемешать |
| Albums | Стрелки / hjkl — навигация; Enter — детали; `p` — играть альбом; `a` — добавить; `f` — Tidal favorite; `r` — обновить |
| Library | ↑/↓ — выбор; Enter — открыть/добавить; Backspace/`h` — вверх; `a`/`A` — добавить / добавить и играть; `r` — обновить |
| Playlists | Tab — смена панели; Enter — открыть список / добавить трек; `a` — добавить плейлист; `D` — удалить |

Контекстные команды имеют приоритет: например, Space в Radio не ставит Mopidy на паузу.
Щелчок по вкладке открывает её. Щелчок по результату радио равнозначен Space,
по станции в воспроизведении — Enter. В остальных поддерживаемых областях
щелчок выбирает строку и выполняет действие Space, а не Enter.

## Сеть, поиск и буферизация

Список зеркал Radio Browser запрашивается через DNS SRV `_api._tcp.radio-browser.info`.
Если это не удалось, используются адреса `all.api.radio-browser.info` и обратные PTR-запросы.
Полученный список очищается от дубликатов и перемешивается. При ошибке выбирается
следующее зеркало; `de1` не закреплён первым. Конфигурационный `servers` используется
только когда обнаружение не вернуло подходящих адресов.

Поиск по имени и тегам выполняется параллельно, результаты объединяются без дубликатов.
Есть ограничение времени на запрос, на маршрут и общий предохранитель поиска в TUI
около 30 секунд. Поэтому за один поиск могут быть опробованы не все зеркала.
HTTP 503 означает ответ недоступного сервера; смена прокси не исправит сам сервер.
Клиент отправляет User-Agent с названием и версией приложения.

Порядок маршрутов определяется F2: предпочтительный, затем альтернативный.
Прямой маршрут не наследует `HTTP_PROXY`/`ALL_PROXY`. Прокси используется для поиска,
проверок и радио; обычный Mopidy имеет собственные сетевые настройки.
DNS-обнаружение зеркал использует системный DNS, даже при SOCKS-прокси.
При его недоступности нужен пригодный резервный список. Поиск не является офлайн-каталогом.

Буфер сглаживает краткие задержки, но не устраняет постоянную нехватку скорости.
Попробуйте 3–5 секунд в F2. Больший буфер увеличивает задержку запуска.
`0` отключает дополнительный буфер. Для источников GStreamer без preroll
используется их штатная буферизация, чтобы не заблокировать запуск.

Описание API: [Radio Browser](https://api.radio-browser.info/).

## Управление через mpc

Для управления независимым радио обычным `mpc` нужен **mopytui-mpd-proxy**:

```text
mpc / медиаклавиши → 127.0.0.1:6600 → MPD-шлюз
                                      ├─ активное радио → сокет mopytui
                                      └─ обычная музыка → Mopidy:6602
TUI → Mopidy HTTP:6680, MPD:6602
```

**Один TUI без установленного шлюза не перехватывает mpc.**
На 6600 должен слушать шлюз, на 6602 — Mopidy.

Закройте mopytui. Из готового архива, от того же пользователя, который запускает
Mopidy и TUI, выполните:

```sh
python3 install-mpc-gateway.py
```

После сборки сначала положите бинарник рядом с установщиком:

```sh
cp target/release/mopytui-mpd-proxy ./mopytui-mpd-proxy
python3 install-mpc-gateway.py
```

Установщик рассчитан на **пользовательскую** службу `mopidy.service`,
переносит её MPD-порт на 6602, правит `mpd_port` TUI, устанавливает шлюз в
`~/.local/lib/mopytui-radio/` и включает `mopytui-mpd-proxy.service`.
Резервные копии: `~/.local/state/mopytui-radio/backups/`.
При неудачной установке выполняется откат. Системную службу Mopidy и нестандартные
схемы запуска этот установщик автоматически не настраивает.

```sh
mpc status
mpc toggle
mpc play
mpc pause
mpc stop
mpc next
mpc prev
mpc volume +3
mpc volume -3
```

При активном радио команды относятся к радио; next/prev переключают станции.
Команды перемотки радио игнорируются. Это поток, а не файл с доступной временной шкалой.
После выключения радио команды снова адресуются Mopidy. Режимы random/repeat/single
Mopidy не заменяют собственный таймер Radio Loop.

Шлюз и TUI должны работать от одного пользователя и использовать один управляющий сокет:
по умолчанию `~/.cache/mopytui/radio-control.sock`.
Переопределение `MOPYTUI_CONTROL_SOCKET` должно совпадать у обоих процессов.

## Awesome WM

Необязательная интеграция лежит в `integrations/awesome/`.
Она показывает станцию, исполнителя и трек из метаданных потока через MPD-шлюз.
Если станция не передаёт теги, восстановить имя композиции приложение не может.

Из релизного каталога, указав **существующие** файлы своей конфигурации:

```sh
python3 install-awesome-integration.py /path/to/lain/widget/mpd.lua \
  --theme /path/to/theme.lua
```

Установщик сохраняет резервные копии, заменяет модуль и только секцию темы
между `-- MPD` и `-- MEM`. Это интеграция с определённой структурой темы,
а не универсальная замена любого theme.lua. Затем перезапустите Awesome.

Шрифт наследуется из темы; станция — `color_accent_2`, исполнитель — `color_accent_3`,
трек — `color_fg_base`. Название станции ограничивается 32 символами.
Пауза и остановка показывают отдельные подписи, а не старый трек.
Опрос выполняется каждые 0,5 секунды без перекрытия запросов; частота новых метаданных
при этом зависит от самой радиостанции.

## Отдельный radio-search

CLI не требует Mopidy и не меняет его воспроизведение:

```sh
radio-search ambient
radio-search --json ambient
radio-search --probe ambient
MOPYTUI_RADIO_PROXY=socks5h://127.0.0.1:1080 radio-search --json ambient
```

Без `--json` выводятся имя, кодек, битрейт и URL, разделённые табуляциями.
`--probe` последовательно проверяет декодирование каждой станции и оставляет
успешные; для большого списка это может занять несколько минут.
CLI использует стандартные настройки и переменную `MOPYTUI_RADIO_PROXY`,
**не читает конфиг TUI**. Бинарник устанавливается отдельно, чтобы не перезаписывать
уже существующий пользовательский скрипт `radio-search`.

## Темы и акцентные цвета

Темы: `midnight` (по умолчанию), `soft-dark`, `daylight`, `solar`.
Выбор: `theme` в конфиге или `--theme`. Фон наследуется от терминала;
для `daylight` используйте светлый фон. Желателен truecolor.

| Назначение | Цветовая роль |
|---|---|
| Клавиши, активная рамка, названия параметров | Основной акцент `accent` |
| Станция, альбом, название Radio Loop | Второй акцент `accent_alt` |
| Исполнитель в общей шапке | Третий акцент `accent_artist` |
| Название трека | Основной яркий текст |
| Успешная проверка / соединение | Зелёный `ok` |
| Ожидание, проверка, пауза | Янтарный `warn` |
| Ошибка проверки / соединения | Красный `err` |

Текущая станция выделена вторым акцентом и маркером ▶.
Цвета проверок сохраняются на выделенной строке. Палитры определяются в
`src/ui/theme.rs`; произвольные RGB-значения в TOML пока не поддерживаются.
Палитра Awesome WM задаётся отдельно в его theme.lua.

## Диагностика

Лог Linux: `~/.cache/mopytui/mopytui.log` (с учётом XDG_CACHE_HOME).
Для подробного журнала запустите `RUST_LOG=mopytui=debug mopytui`.
Перед публикацией журнала удалите пароли, токены и приватные URL.

### mpc не управляет радио

При запущенном Radio Loop выполните от своего обычного пользователя:

```sh
systemctl --user status mopytui-mpd-proxy.service --no-pager
ss -ltnp '( sport = :6600 or sport = :6602 )'
mpc -h 127.0.0.1 -p 6600 status
mpc status
journalctl --user -u mopytui-mpd-proxy.service -n 50 --no-pager
```

Если службу не нашли — шлюз не установлен. Если на 6600 слушает Mopidy,
команды обходят радио. Если явный адрес работает, а обычный `mpc` нет,
проверьте MPD_HOST/MPD_PORT и обёртки shell. Если шлюз активен, но показывает музыку
при играющем радио, сравните пользователя, путь сокета и журнал TUI;
второй экземпляр mopytui не может владеть тем же сокетом.

### Поиск не завершается или выдаёт ошибку

Прочитайте нижнюю строку Radio: там указаны маршрут, зеркало и ошибка.
DNS-ошибка, HTTP 503 и таймаут — разные причины. Для проверки конкретного зеркала:

```sh
curl -q --proxy socks5h://127.0.0.1:1080 --noproxy '' \
  --connect-timeout 5 --max-time 15 \
  'https://de1.api.radio-browser.info/json/stations/search?name=ambient&limit=1'
```

Для прямого подключения замените `--proxy ... --noproxy ''` на
`--proxy '' --noproxy '*'`. Пример не гарантирует доступность этого зеркала.
URL передавайте в одинарных кавычках, без Markdown-скобок.

### Радио перезапускается / нет звука

Проверьте GI/GStreamer командой выше, доступность аудиовыхода и текст Last audio error.
Проверьте другую станцию, прямой/прокси-маршрут и буфер F2.
`Server does not support seeking` относится к потоку: радио не должно получать seek.
Прямые потоковые MP3/AAC-подключения — основной сценарий; плейлист URL может требовать
дополнительного разрешения адреса. HLS/DASH через curl-транспорт не поддерживаются.

### Откат и удаление

Для отката TUI восстановите бинарник из пути, который напечатал install-system.sh.
Удаление `/usr/local/bin/mopytui` не удаляет личные данные.
Перед удалением шлюза отключите его пользовательскую службу и восстановите
прежний порт Mopidy и `mpd_port` TUI из резервных копий; иначе mpc останется без сервера
на 6600. Перезапустите Mopidy после восстановления. Конфиг и коллекции удаляются
только вручную, если они больше не нужны.

## Разработка и ограничения

| Файл / каталог | Назначение |
|---|---|
| `src/main.rs`, `app.rs`, `cmd.rs` | Цикл приложения, состояние и асинхронные команды |
| `src/input.rs`, `events.rs` | Клавиатура, русская раскладка, мышь |
| `src/ui/` | Экраны и темы |
| `src/mopidy/` | JSON-RPC, модели и MPD idle |
| `src/config.rs` | Конфиг и сохранение сетевых настроек |
| `src/radio/search.rs`, `probe.rs` | Каталог зеркал, поиск и проверка аудио |
| `src/radio/player.rs`, `gst_backend.py` | Актор проигрывателя, фейды, маршруты и GStreamer |
| `src/radio/collections.rs`, `remote.rs` | Коллекции и локальный интерфейс шлюза |
| `src/bin/` | Отдельный поиск и MPD-шлюз |
| `tests/` | Проверки транспорта, метаданных, буфера, шлюза и интеграций |

```sh
cargo test --locked -- --test-threads=1
cargo build --release --locked
python3 tests/radio_search_failover.py target/release/radio-search
```

Последовательный запуск тестов избегает гонок временных исполняемых fixtures.
Дополнительные сценарии и исторические результаты: [VERIFICATION.md](VERIFICATION.md).
История реализации радио: [RADIO.md](RADIO.md); актуальное руководство — этот README.

Ограничения: один активный TUI на управляющий сокет; нет фонового радио после выхода
из TUI; нет dual-pipeline crossfade; доступность API и метаданных зависит от источников;
спектр без `audio_pipe` декоративный, не анализ радио. Настоящий FFT ожидает PCM
s16le stereo 44,1 кГц. Настройка вывода такого PCM находится вне самого TUI.
Linux-интеграция с systemd/Unix-сокетами не означает поддержку этих установщиков на Windows.

Перед публикацией включите Cargo.lock, исходники, документацию, тесты и лицензии.
Не включайте target/, личные конфиги, логи и секреты. Готовые бинарники удобно
прикладывать к GitHub Release отдельно от исходников.
