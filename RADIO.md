# mopytui 0.1.0 — Radio Loop

## Сборка и запуск

```sh
cargo build --release --locked
./target/release/mopytui
```

Вкладки: **Queue · Albums · Library · Playlists · Playing · Radio · Info**.
Search и Stats удалены; цифровых префиксов в строке вкладок нет.
Переключение вкладок — Ctrl+← / Ctrl+→ или щелчок по названию.
Tab / Shift+Tab переключают окна внутри вкладки. Быстрые клавиши 1–7 сохранены.

Для радио на машине, где запущен **mopytui**, нужны Python 3, PyGObject и
GStreamer с HTTP, MP3/AAC и аудиовыходом. Например, Debian/Ubuntu:

```sh
sudo apt install python3-gi gir1.2-gstreamer-1.0 gstreamer1.0-plugins-base \
  gstreamer1.0-plugins-good gstreamer1.0-plugins-bad gstreamer1.0-plugins-ugly \
  gstreamer1.0-libav gstreamer1.0-pulseaudio
```

Проверка выбранного Python:

```sh
python3 -c 'import gi; gi.require_version("Gst", "1.0"); from gi.repository import Gst; Gst.init(None); print(Gst.version_string())'
```

Радио-backend использует POSIX stdin: целевая и проверенная платформа — Linux;
Windows-реализация радиоплеера пока не предусмотрена.

GStreamer-помощник встроен в бинарник; устанавливать рядом `.py` не требуется.
При удалённом Mopidy радио играет локально на компьютере с mopytui.

## Управление

Radio одновременно показывает строку поиска, результаты и список воспроизведения.
Поиск с результатами расположен над списком воспроизведения. Активное окно выделено рамкой.

1. В строке поиска ввести название или теги и нажать Enter: фокус переходит
   в результаты, запускается поиск.
2. Space в результатах проверяет декодируемое аудио и автоматически добавляет
   пригодную станцию в список воспроизведения. Повторное добавление не создаёт дубль.
   Проверка показана зелёным OK или красным DEAD.
3. Enter в результатах проверяет, добавляет и запускает именно выбранную станцию.
   Повторно нажимать Enter после завершения проверки не нужно.
4. Enter в списке воспроизведения переключает на выбранную станцию с настроенными
   fade-out / fade-in. Space в этом списке игнорируется.

| Клавиша в Radio | Действие |
|---|---|
| Tab / Shift+Tab | Поиск → результаты → воспроизведение / обратно |
| Ctrl+← / Ctrl+→ | Предыдущая / следующая вкладка |
| ↑ / ↓, j / k | Выбрать станцию в активном списке |
| n или > / < | Следующая / предыдущая станция |
| r | Перезапустить поток через fade-out/in |
| p | Пауза / продолжить; если остановлено — запустить |
| s | Остановить радио через fade-out |
| d / Delete | Удалить выбранную станцию из воспроизведения |
| J / K | Переместить станцию вниз / вверх |
| a или / | Фокус на строку поиска |
| + / - | Громкость активного проигрывателя |
| F2 / F3 | Интервалы и fade / коллекции |
| q | Выйти из приложения |

Один щелчок по результату равен Space; по станции в воспроизведении — Enter.
На остальных экранах щелчок выбирает строку и выполняет действие Space.
Горячие клавиши работают на тех же физических кнопках русской раскладки;
в строке поиска и имени коллекции русские буквы вводятся без преобразования.

В строке ввода q, цифры, пробел и другие печатные клавиши вводят текст.
Ctrl+C доступен для выхода из Radio даже во время редактирования.

## Поведение

- Порядок станций циклический; случайно выбирается только время:
  целое число минут в диапазоне **23–37**, включая границы, при каждом запуске
  станции и ручном Next. Отсчёт начинается при первом декодированном аудио.
  Автоматическое восстановление того же потока сохраняет его таймер.
- Перед началом приложение ждёт успешного `core.playback.pause` от Mopidy.
  При ошибке или таймауте радио не запускается. Очередь и позиция Mopidy
  не меняются; остановка радио не вызывает resume/play Mopidy.
- Запуск обычной музыки из mopytui сначала останавливает радио.
  При обнаружении воспроизведения Mopidy, начатого другим клиентом, радио
  также останавливается после обновления состояния Mopidy.
- Одна pipeline: **fade-out 1.5 с → остановка → подключение новой станции →
  fade-in 2.5 с**. Между потоками может быть пауза подключения.
- Ошибка/EOS: ожидание 3 с, одна повторная попытка того же URL, до 5 с на
  получение аудио. Если не удалось — следующая станция. Исчезновение
  декодированных буферов на 3 с считается обрывом и запускает повтор.
  При первоначальном подключении также действует лимит 5 с.
- При успешном восстановлении будущий новый обрыв считается новым инцидентом.
  Если недоступны все станции, цикл продолжает повторные обходы до Stop.
- Пауза замораживает таймер и фазы переключения. Next снимает паузу.
- Добавление/перестановка/удаление другой станции не сбрасывает таймер.
  Удаление или выключение текущей переводит к следующей; пустой список
  или выключение всех станций останавливает цикл.
- Список сохраняется в памяти до выхода из приложения, не на диск.

## Конфигурация

Добавить в конец `~/.config/mopytui/config.toml` (старые конфиги совместимы):

```toml
[radio]
rotation_min = 23
rotation_max = 37
fade_out = 1.5
fade_in = 2.5
retry_wait_before_restart = 3.0
retry_wait_after_restart = 5.0
station_probe_timeout = 5.0
python = "python3"
servers = ["https://de1.api.radio-browser.info"]
```

Интервалы rotation — минуты, остальные времена — секунды. Можно указать
`python = "/usr/bin/python3"`, если Python из virtualenv не видит `gi`.
Начальная независимая громкость Radio — 80%; её регулируют +/−.

## Отдельный CLI

Исходного пользовательского Python-скрипта `radio-search` в архиве нет.
Он не изменялся и не заменяется автоматически. Дополнительный CLI проекта:

```sh
./target/release/radio-search 'dark ambient'
./target/release/radio-search --json 'SomaFM Drone Zone'
./target/release/radio-search --probe 'ambient'
```

Вывод по умолчанию — TSV: название, кодек, битрейт, URL; `--json` — JSON.
`--probe` оставляет только станции с декодируемым аудио, проверяет последовательно.
Этот CLI не требует Mopidy, не добавляет станции в его очередь и не заменяет
функции старого скрипта `mpc` / `fzf` / сохранения M3U. Не устанавливайте его
под именем существующего скрипта, если хотите сохранить оба интерфейса.

## Архитектура

- `src/radio/search.rs` — общее ядро Radio Browser, name OR tags,
  дедупликация UUID, таймауты, резервные серверы.
- `src/radio/probe.rs` — запуск проверки, таймаут, завершение процесса.
- `src/radio/gst_backend.py` — playbin, raw-audio handoff, volume, JSON-lines.
  Probe использует fakesink, поэтому не звучит. HTTP-ответ, metadata и
  переход pipeline в PLAYING сами по себе не считаются успешной проверкой.
- `src/radio/player.rs` — фоновый actor, состояния, собственные часы,
  gain, retry и независимый `Deck`. Для dual-pipeline crossfade следует
  держать outgoing/incoming Deck одновременно и применять обе кривые gain;
  сейчас одновременно играет только один Deck.
- `src/radio/mod.rs` — состояние UI, асинхронный поиск/проверки,
  координация запуска после паузы Mopidy.
- `src/ui/radio.rs` — экран и клавиши до глобальных Mopidy bindings.

Полезные первичные документы:
[GStreamer custom playbin sinks](https://gstreamer.freedesktop.org/documentation/tutorials/playback/custom-playbin-sinks.html),
[Radio Browser API](https://docs.radio-browser.info/).

## Обновление сети (radio-loop-v2)

Поиск теперь использует системное разрешение DNS. При ошибке подключения
или таймауте встроенного клиента запрос повторяется через установленный
`curl`, с обычной проверкой HTTPS-сертификата. При успешном резервном запросе
оставшаяся часть поиска использует curl. HTTP-ошибки вроде 429 не вызывают
этот резервный повтор. Ошибки DNS/TLS/сокета показываются с основной
причиной в начале сообщения, а подробности записываются в журнал mopytui.


## Аудиодиагностика v3 — версия 0.1.1-radio.3

Исходная ошибка GStreamer больше не заменяется общим сообщением о выходе.
Stderr аудиопроцесса сохраняется в журнал mopytui. Последняя ошибка остаётся
внизу Radio Loop (`Last audio error`) после Stop. На Linux журнал обычно:
`~/.cache/mopytui/mopytui.log`.

Одна секунда аудио после повторного подключения больше не обнуляет счётчик
попыток: до окончания окна восстановления повторный обрыв переводит на
следующую станцию. Это окно равно `retry_wait_after_restart` (по умолчанию 5 с).
Точная причина сбоя на машине пользователя пока не установлена: для неё
нужна исходная ошибка из новой диагностики. Настройка аудиопрокси не менялась.


## Версия 0.1.1-radio.4: прямой эфир через прокси и обычный mpc

### Установка для существующих горячих клавиш на порту 6600

Закрыть mopytui. В распакованной папке выполнить **от своего пользователя, без sudo**:

```sh
python3 install-mpc-gateway.py
./start-radio-proxy.sh
```

Установщик рассчитан на работающую пользовательскую службу `mopidy.service`
и обычный конфиг `~/.config/mopidy/mopidy.conf`. Он:

1. Сохраняет резервные копии в `~/.local/state/mopytui-radio/backups/`.
2. Меняет только `port` в `[mpd]` Mopidy на **6602**, а корневой `mpd_port`
   в конфиге mopytui — на **6602**. HTTP 6680 и секция `[radio]` сохраняются.
3. Копирует шлюз в `~/.local/lib/mopytui-radio/mopytui-mpd-proxy` и создаёт
   `~/.config/systemd/user/mopytui-mpd-proxy.service`.
4. Один раз перезапускает Mopidy и включает пользовательскую службу шлюза.
   Шлюз занимает **6600**. Обычный `mpc` и горячие клавиши менять не требуется.
5. Если настройка/запуск не удались, восстанавливает прежние файлы и пытается
   снова запустить Mopidy с прежней конфигурацией.

Установщик не выполнялся на машине пользователя при подготовке архива.
Если служба/пути отличаются, он останавливается с сообщением; не следует
запускать его через sudo для обхода такой проверки.

### Команды

```sh
mpc volume +5
mpc volume -5
mpc volume 35
mpc next
mpc prev
mpc pause
mpc play
mpc toggle
mpc seek +10     # при активном Radio Loop: игнорируется, возвращается OK
```

При активном (в том числе приостановленном) радио эти команды направляются
в Radio Loop. `status` и `currentsong` показывают радио; громкость независима
от Mopidy. `stop` останавливает радио. Команды `seek`, `seekid`, `seekcur`
во время радио подтверждаются без выполнения и **не передаются в Mopidy**.
Остальные команды MPD передаются Mopidy.

Когда Radio Loop остановлен или TUI закрыт, команды, включая перемотку,
снова идут в обычный Mopidy. Шлюз — самостоятельная служба, поэтому закрытие
TUI не отключает `mpc`. Сам TUI получает MPD-события напрямую с порта 6602.
Закрытие TUI/радио не запускает обычное воспроизведение автоматически.

Интерфейс `mpc idle` для событий самого радио пока не реализован: такие
подписки отражают события Mopidy. Требуемые команды и запрос статуса работают.

### Прокси и непрерывный поток

`start-radio-proxy.sh` устанавливает `socks5h://127.0.0.1:1080` для поиска
и переменную `MOPYTUI_RADIO_PROXY` для **самих радиопотоков**, включая HTTP.
Mopidy на localhost остаётся доступен напрямую.

С этой переменной curl получает поток через прокси и передаёт его через
pipe в GStreamer `fdsrc → decodebin → аудиовыход`. Pipe не поддерживает
перемотку; HTTP Range и resume не используются. Повторные подключения
выполняет только Radio Loop. По-прежнему проверяется декодируемое аудио,
пробные проверки не звучат.

Транспорт через curl рассчитан на прямые MP3/AAC/Ogg и другие декодируемые
аудиопотоки. HLS/DASH manifest URL этим транспортом не поддерживаются и
не пройдут проверку. Без `MOPYTUI_RADIO_PROXY` остаётся playbin; его
внутренние HTTP-повторы отключены, чтобы не возобновлять радио с байтового смещения.

Пауза радио теперь глушит звук, но продолжает получать эфир. Таймер заморожен;
Play возвращает к текущему прямому эфиру без перемотки и накопленного буфера.

Для другого прокси:

```sh
MOPYTUI_RADIO_PROXY=socks5h://127.0.0.1:1081 ./start-radio-proxy.sh
```

Если после прежней диагностики выставлено по 15 секунд ожидания,
можно вернуть в `[radio]` исходные значения:

```toml
retry_wait_before_restart = 3.0
retry_wait_after_restart = 5.0
```

### Диагностика службы

```sh
systemctl --user status mopytui-mpd-proxy
journalctl --user -u mopytui-mpd-proxy -n 30 --no-pager
./mopytui --version   # mopytui 0.1.1-radio.4
```

Первичная документация:
[GStreamer souphttpsrc: retries/is-live](https://gstreamer.freedesktop.org/documentation/soup/souphttpsrc.html).


## v5: обычный запуск с сохранённым прокси

В существующую секцию `[radio]` файла `~/.config/mopytui/config.toml`
добавьте строку (не создавайте вторую секцию с тем же именем):

```toml
[radio]
proxy = "socks5h://127.0.0.1:1080"
```

После этого запускайте `./mopytui`. Этот прокси используется для Radio Search,
проверки декодирования и проигрывания радио. Соединения с Mopidy не меняются.
Прокси должен быть запущен. Пустое значение сохраняет прежнее поведение.
Переменная MOPYTUI_RADIO_PROXY имеет приоритет над конфигом; старый скрипт
start-radio-proxy.sh продолжает работать. Отдельный CLI radio-search принимает
эту переменную окружения, но не читает конфиг TUI.

Подписи Now, Next, Status, Switch in, Volume, Range, Fade out и Fade in
выделены жирным и цветом акцента текущей темы. Значения остаются обычным текстом.


## v6: явный прокси без обхода через окружение

При заданном proxy curl запускается с `-q --proxy URL --noproxy ""`.
Пользовательский .curlrc не читается; NO_PROXY не обходит явно выбранный прокси.
Это относится к поиску и аудиопотоку. Строка Network показывает выбранный
адрес без логина/пароля; если настройка отсутствует, это указано явно.
Таймаут поиска остался 10 секунд: контрольный запрос пользователя прошёл за 0.84 с.


## v7: редактор Radio и оформление

F2 открывает настройки в Radio: ↑/↓ или Tab выбирают поле, ←/→ либо +/-
меняют значение, Enter применяет, Esc отменяет. Интервалы: шаг 1 минута;
Fade out / Fade in: шаг 0.1 с. Настройки действуют только в текущем сеансе.
При изменении диапазона запускается новый случайный таймер от текущего
момента; пауза сохраняется. Изменение только фейдов не сбрасывает таймер.
Проверенные станции показывают зелёный OK, ошибки — красный DEAD.
Клавиши в подсказках выделены жирным и акцентом темы.

Для обычного mpc на 6600 требуется одна установка шлюза:
закройте TUI, выполните `python3 install-mpc-gateway.py` без sudo,
затем запустите `./mopytui`. Если служба mopytui-mpd-proxy.service
отсутствует, а 6600 слушает mopidy, команды пока идут напрямую в Mopidy.


## v8: один регулятор громкости

Верхняя шкала Vol показывает активный проигрыватель: Radio Loop (включая
паузу радио) либо обычный Mopidy, если цикл остановлен. Строка Volume
из шапки Radio удалена. Клавиши +/- на любой вкладке управляют тем же
активным проигрывателем. mpc продолжает управлять радио через шлюз.
Громкость Mopidy не перезаписывается при работе Radio Loop.

## v9: Radio Collections и метаданные для апплета

F3 во вкладке Radio открывает Collections:

- `s` — сохранить текущий список под новым именем, Enter подтверждает;
- `Enter` — загрузить выбранную подборку; воспроизведение запускается отдельно;
- `r` — переименовать;
- `u` — заменить выбранную подборку текущим списком и настройками, `y` подтверждает;
- `d` — удалить, `y` подтверждает, `n`/Esc отменяет;
- ↑/↓ — выбрать, Esc — вернуться.

Сохраняются порядок станций, их включение/отключение, диапазон интервала,
fade-out и fade-in. Загрузка требует остановленного Radio Loop. Прокси,
пути к Python и настройки повтора не заменяются. Файл:
`~/.config/mopytui/radio-collections.json` (с учётом XDG_CONFIG_HOME).
Запись атомарная; повреждённый файл не перезаписывается при открытии.
Изменения F2 сохраняются в подборке при `s` или `u`.

В запросе аудио включены ICY-метаданные. GStreamer извлекает теги потока;
радиоплеер передаёт их MPD-шлюзу. При смене станции старые теги очищаются.
В архиве `integrations/awesome/mpd.lua` — обновлённый присланный апплет,
`install-awesome-widget.py` — установка по указанному пути с резервной копией.
Подробности — `integrations/awesome/README.md`.

## Сеть, буфер и сигналы (v12)

В Radio нажмите **F2**. Стрелками ↑/↓ выберите поле, ←/→ измените:

- **Preferred network** — `proxy` или `direct`. Адрес прокси берётся из
  существующего `radio.proxy` / `MOPYTUI_RADIO_PROXY`. Без адреса доступен
  только прямой маршрут.
- **Audio buffer** — 0–30 секунд; начальное значение **3 секунды**. Ноль
  отключает дополнительный буфер. Больший буфер увеличивает задержку старта
  и отставание от прямого эфира, но может скрыть короткие сетевые провалы.
- **Start / stop sounds** — короткие звуки старта и остановки Radio Loop.
  Стартовый звук звучит до подключения/буферизации; остановочный — после
  закрытия потока. При переключении станций и автоматическом восстановлении
  звуков нет. При нулевой громкости радио звуки также отключены.

**Enter** применяет настройки и сохраняет эти три параметра в config.toml,
сохраняя остальные ключи и комментарии. **Esc** отменяет изменения. Новый
маршрут и размер буфера используются при следующем подключении потока;
текущее воспроизведение ради изменения предпочтения не прерывается.
Настройки интервалов и fade по-прежнему применяются в текущей сессии.

```toml
[radio]
proxy = "socks5h://127.0.0.1:1080"
preferred_network = "direct" # или "proxy"
buffer_seconds = 3.0
sound_signals = true
```

Поиск и проверка аудио сначала используют предпочтительный маршрут,
при ошибке — альтернативный. У потока сначала выполняется обычная
повторная попытка того же URL, затем подключение через альтернативный
маршрут с одной повторной попыткой. Если оба маршрута не работают,
цикл переходит к следующей станции. На следующей станции проверка опять
начинается с предпочтительного маршрута. Прямой маршрут явно отключает
унаследованные HTTP_PROXY/HTTPS_PROXY/ALL_PROXY.

В строке Network показывается маршрут текущей попытки подключения;
Buffering N% означает заполнение буфера, а не обрыв. Предзагрузка и повторное
заполнение имеют ограниченное время ожидания, после чего работает
восстановление соединения. Probe проверяет первый декодированный пакет
без предзагрузки буфера (таймаут около 5 секунд на каждый маршрут).

Буфер использует очередь декодированного аудио GStreamer. Для источников,
которые сообщают NO_PREROLL (истинный live source), сохраняется их собственная
буферизация, чтобы ожидание заполнения не заблокировало источник.

## Поиск при сбое каталога (v13)

HTTP 503 от Radio Browser означает недоступность отвечающего сервиса.
Смена прокси сама по себе не поможет, если оба маршрута ведут к тому же
неработающему серверу. Начиная с v13 список `radio.servers` дополняется
актуальными именами зеркал через DNS SRV `_api._tcp.radio-browser.info`
или A/AAAA + PTR `all.api.radio-browser.info`, согласно документации
https://api.radio-browser.info/ . Устаревшие адреса зеркал не зашиты в код.

Поиск по имени и тегам идёт параллельно через curl. Каждому маршруту
выделено до 12 секунд, обнаружению серверов — до 3 секунд. В интерфейсе
видны текущий сервер, маршрут и прошедшее время. Дополнительный контроль
снимает состояние поиска через 30 секунд. Если все серверы недоступны,
выводится ошибка; новые результаты из неработающего каталога получить
невозможно. Сохранённые коллекции и воспроизведение от поиска не зависят.

## Выбор серверов по документации (v14)

Успешное обнаружение DNS теперь **заменяет** адреса из `radio.servers`.
Полученный список нормализуется, очищается от повторов и перемешивается
перед каждым поиском. Постоянного приоритета de1 больше нет. Если DNS не
дал пригодных адресов, перемешивается запасной список из конфига.

Сначала запрашивается SRV `_api._tcp.radio-browser.info`; при отсутствии
ответа — A/AAAA `all.api.radio-browser.info` и параллельные PTR-запросы.
У стадий отдельные ограничения времени: один медленный PTR не приводит
к потере успешно найденных имён. После ошибки проверяется следующий
сервер, пока не исчерпан бюджет текущего маршрута. User-Agent содержит
фактическую версию mopytui-radio. Эти правила применяются также к CLI
radio-search. Они заменяют порядок добавления зеркал, описанный для v13.
