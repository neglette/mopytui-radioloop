# Проверка Radio Loop fork — 2026-10-02

Исходник: пользовательский `mopytui.zip`, версия 0.1.0,
базовый Git commit `9ba4bcd382c6d95479aea25aab434198a7bdb68e`.

Платформа сборки: Linux x86_64, Rust 1.99.0, GStreamer 1.24.2,
Python 3.12. Бинарники требуют glibc 2.39 или новее. Для старой системы
собрать из исходников на ней: `cargo build --release --locked`.

Выполнено:

- `cargo build --release --locked --offline` — оптимизированная сборка обоих CLI.
- `cargo test --locked --offline` — 11 тестов, ошибок нет:
  редактирование списка и сохранение таймера; исключение отключённых станций;
  удаление текущей/всех станций; одна повторная попытка; actor с тестовым
  процессом (обрыв → restart → next, пауза таймера, ручной Next, Stop);
  настройки и валидация; запрет старта при ошибке паузы Mopidy и отмена
  отложенного старта; только проверенные checkbox-станции; таймаут зависшего
  декодера; маршрутизация клавиш; семь вкладок без цифровых префиксов.
- `python3 tests/gstreamer_probe.py` — два теста пройдены, один HTTP-тест
  пропущен по условию среды: валидный WAV декодируется; текст не проходит;
  закрытие stdin завершает backend.
- Реальный `radio-search --json 'SomaFM Drone Zone'` — 5 результатов API.
- Реальный GStreamer probe: SomaFM Drone Zone MP3 128k и AAC 64k — оба
  получили декодированное аудио примерно за 1.27 секунды, в пределах 5 с.
- Smoke checks `mopytui --version` и `radio-search --help`.
- `git diff --check` и проверка применения патча к исходному дереву.

Ограничения проверки:

- Доступа к пользовательскому Mopidy и аудиоустройству не было; реальную
  связку с ним и слышимое качество fade на оборудовании нужно проверить там.
- TCP loopback в среде выполнения отклоняет соединения с локальным сервером,
  поэтому дополнительный HTTP fixture test оставлен для запуска вне этой
  среды: `MOPYTUI_HTTP_TEST=1 python3 tests/gstreamer_probe.py`.
- Проверки MP3/AAC выполнялись через fakesink (декодирование без звука).
- 23–37-минутный эфир в реальном времени не прогонялся; диапазон и
  переходы проверялись тестами и кодом. Двухпоточный crossfade не реализован:
  первая версия использует последовательный fade-out / switch / fade-in.

## Аудиодиагностика v3 (0.1.1-radio.3)

Исправлено затирание исходной ошибки GStreamer сообщением EOF; stderr теперь
читается и записывается в журнал, последняя ошибка остаётся на экране Radio.
BrokenPipe управляющего канала не затирает ошибку декодера. Исправлен сброс
бюджета повторов при кратковременном восстановлении потока.

Добавлены проверки: error + EOF дают ровно одну исходную ошибку;
выход без JSON сохраняет stderr; обрыв на fade-in после повторного подключения
переводит на следующую станцию. Полный набор: 15 тестов пройдено, сетевой
opt-in тест пропущен. Причина обрыва на машине пользователя пока не установлена.
